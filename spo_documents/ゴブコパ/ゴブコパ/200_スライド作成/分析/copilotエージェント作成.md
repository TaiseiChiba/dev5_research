２つのプロンプト（**通常版** と **Copilot’s Pilot 版**）を拝見し、どのような点が改善されたかを **構造的に比較** してまとめました。

---

# 🔍 結論：最大の改善ポイントは「エージェントに“根拠を自動取得させる”仕組みが導入されたこと」

あなたの試行錯誤の軌跡を見ると、最初のプロンプトは「エージェントに守ってほしい振る舞い」を文章で説明するだけでしたが、  
**最終形では “エージェント作成エージェント” が、さらに高度な制約・手順・検索義務 を体系的に組み込み、プロンプト品質が一気に上がっています。**

---

# 🆚 改善点の比較（重要なポイントだけ抽出）

## ① **根拠検索の強制力が強化された**

### ◆ 初期プロンプト

- 「資料を根拠にして回答してください」と指示するのみ
- 実際には根拠の検索や参照が曖昧になりがち
- SQL を勝手に答えたり、画面仕様書だけで判断してしまうなど誤動作が発生

### ◆ Copilot’s Pilot 版

- **回答前に SharePoint 内の文書検索を必須化**（明示的なガードレール）
- 見つからなければ「不明」と答えることを強制
- 根拠として「ファイル名＋行番号」の提示を義務化
- 推測回答を完全禁止

👉 **AI が勝手に推測する余地が激減し、業務文書ベースの正確な回答に一本化できるようになった点が大きな改善。**

## ② **業務ルールを順守するための仕組みが細分化された**

### 初期版

- 「業務ルールに従う」程度の大まかな指示
- 実務上必要な、承認フロー・権限・禁止行為の扱いがあいまい

### Copilot’s Pilot 版

- **承認が必要な操作は必ず承認者の役割と手順を明記**
- **ユーザーの意図が業務ルールに反する場合も、代替操作を強制的に提示**
- 「業務ルールに反する操作は出力禁止」を強く明文化
- 「通常操作で到達可能なら“到達手順”を提示する」
- 「不可能と回答してよい条件」を定義

👉 **業務フローとシステム仕様への完全準拠を、AI の内部ロジックに組み込む設計になっているのが大きい改善。**

---

```
千葉コメント
・業務ルールはシステムごとに異なってくるので、有識者が設定してあげる必要があると感じた。
```

## ③ **回答フォーマットが“明文化されたプロセス”に進化**

### 初期版

- 回答フォーマットは存在するが甘く、AI の解釈ブレが起きやすかった

### Copilot’s Pilot 版

- **5 ステップの厳密な回答プロセスを明文化**

  1.  最終状態の整理
  2.  必要業務・画面の抽出と引用
  3.  引用できないものは不明扱い
  4.  全て根拠づけ可能な場合のみシナリオ生成
  5.  到達不可能なら根拠を必ず提示したうえで「不可」と判断

- **完全に手順化されており、ブレが出にくい**

👉 “手順化されたプロセス” をエージェントに実装できている点が、実用エージェントとして非常に完成度が高い。

---

```
千葉コメント
・回答に一貫性が出て、使用する側も見やすい。
```

## ④ **推測・常識補完・勝手な判断を絶対にさせない構造に進化**

初期では以下のような問題が発生していました：

- SQL を勝手に答える
- 常識から補完した動作を回答する
- 「一般的には〜」を言いがち
- 勝手にワンタイムパスワードを要求するなど虚構が混じる

最終版では：

- 「推測禁止」
- 「文書にない項目はすべて不明扱い」
- 「一般的には/通常は」の表現禁止
- 虚構を作ることを明示的に禁止

👉 **AI 特有の“幻覚”を完全に抑制する仕組みが組み込まれている。**

---

```

・ハルシネーション抑止
```

## ⑤ **ユーザーの質問が不完全でも、仕様書に基づき補完して正しい手順を生成できるように**

特に Copilot’s Pilot 版では：

- **ユーザーの質問が曖昧でも、仕様書を根拠に補完する能力を追加**
- ただし「仕様書にある範囲内でのみ補完」という強固な制約付き

👉 専門的な業務アシスタントとしての精度が大幅に上昇。

---

## ⑥ **複雑な“迂回ルート（代替フロー）”まで自動生成できるようになった**

初期：

- 「その操作はできません」で終わりがち

最終版：

- **複数画面を経由する段階的な到達手順を構成し、業務ルールを順守した上で目的状態に導く流れを必ず提示**
- “直接作れない状態” に対しても、“正規の画面遷移と操作だけで到達するルート” を提案できる

👉 実務で使えるエージェントに必要な「現実的な業務代替案」が実装された。

---

　例）残高0のテストデータ作成方法
　→口座作成して、すぐ残高を0円にするシナリオは通常考えられない。

# 🎯 総評：あなたは **“エージェントに推測させず、業務仕様だけで考えさせる設計”** を確立した

特に Copilot’s Pilot の生成した最終版は、  
**内部的に RAG（検索＋回答）構造をプロンプトだけで擬似的に組み込んでいる** と言えるレベルで優秀です。

- 文書検索（R）を強制
- 根拠に基づく回答（A）
- 推測禁止（G）

これにより **幻覚ゼロに近い業務エージェントが成立** しています。
